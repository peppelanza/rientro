# Deploying Rientro on Render

Rientro runs as one Node service with a persistent disk (SQLite database + uploaded photos and
videos). `render.yaml` in the repo root describes everything; Render reads it automatically.

## 1. Create the service (once, ~10 minutes)

1. Merge PR #2 so `master` contains the app.
2. Sign up at <https://render.com> with your GitHub account.
3. **New → Blueprint**, pick the `peppelanza/rientro` repository, confirm.
4. Render asks for these values:

   | Variable | What to put |
   |---|---|
   | `BASE_URL` | `https://rientro.onrender.com` for now (Render shows the exact address); later your domain, e.g. `https://rientro.it` |
   | `ADMIN_EMAILS` | your email. Signing in with it gives you the admin area |
   | `PREVIEW_PASSWORD` | a password to share with testers. Leave **empty** only when you go public |
   | `LAUNCHED` | `1` to open discovery and connections now; empty keeps them closed until 1 Jan 2027, and the homepage shows a live countdown instead of the example profiles |
   | `BREVO_API_KEY` | empty for the preview (the code is shown on screen, behind the password) |
   | `MAIL_FROM` | empty for the preview |

   `PSEUDONYM_SECRET` is generated by Render. **Never change it later**: it links consent records.
5. **Apply**. The first deploy takes 2–3 minutes. Open the address, enter the preview password
   (any username), then sign in with your admin email.

Cost: Starter plan (about $7/month) + 5 GB disk (about $1.25/month), Frankfurt region.

## 1b. If you created a Docker web service instead of a Blueprint

That works too (the repo has a `Dockerfile`). In the service settings:

1. **Region**: Frankfurt. **Instance type**: Starter or higher (disks need a paid plan).
2. **Disks → Add disk**: mount path `/var/data`, 5 GB. Without it, data is lost on every deploy.
3. **Environment → Add variables**:
   - `PSEUDONYM_SECRET`: a long random string (e.g. from a password manager). Never change it later.
   - `BASE_URL`, `ADMIN_EMAILS`, `PREVIEW_PASSWORD`, `LAUNCHED`: as in the table above.
4. **Health check path** (Settings): `/healthz`.
5. **Manual Deploy → Deploy latest commit**.

## 2. Going public (before launch)

1. **Email for sign-in codes.** Create a free account at <https://www.brevo.com> (EU; 300 emails/day free).
   Verify your domain or sender address, then create an API key (SMTP & API → API keys).
2. In Render → rientro → Environment: set `BREVO_API_KEY` and `MAIL_FROM` (the verified sender),
   then **delete** `PREVIEW_PASSWORD`. Save; Render redeploys.
3. Custom domain: Render → Settings → Custom Domains → add `rientro.it`, follow the DNS steps,
   then update `BASE_URL`.
4. Legal texts: replace the drafts after review by a privacy professional (see `docs/PRIVACY_ARCHITECTURE.md`).

## 3. Launch day

- **Scale up** the day before: Render → Settings → Instance Type → e.g. *Standard* or *Pro*
  (more CPU and RAM). It takes a minute; scale back down afterwards.
- Keep **one instance**: the database is a file on its disk, so don't raise the instance count above 1.
- **Backups**: Render snapshots persistent disks daily (restore from the Disks tab). Before big
  changes you can also download `/var/data/rientro.db` from the Shell tab.

## Troubleshooting

- *Deploy fails with "Set BREVO_API_KEY (with MAIL_FROM) or PREVIEW_PASSWORD in production"*:
  production needs one of the two, otherwise nobody could sign in.
- *"Non riusciamo a inviare il codice"*: check the Brevo key and that `MAIL_FROM` is verified; the
  Render logs show Brevo's error.
- Logs: Render → rientro → Logs.
